### Login bug — the COMPLETE fix (important)
GoTrue reads EIGHT `auth.users` columns as required strings; ANY NULL among them throws
"Database error querying schema" on password sign-in. The first pass only fixed the 6 token
columns, so the error just moved to `email_change` (then it would've moved again). The full
set that must be `''` (never NULL): `confirmation_token, recovery_token, email_change_token_new,
email_change_token_current, phone_change_token, reauthentication_token, email_change, phone_change`.
All are now `''` for every user (0 NULLs); `phone` staying NULL is fine (GoTrue treats it as
optional). **If this error EVER reappears for any account, run:** `UPDATE auth.users SET
<each of the 8> = COALESCE(<col>,'') WHERE <any> IS NULL;` I could not `ALTER ... SET DEFAULT ''`
(needs table owner), but new users made through the app's Team page go via GoTrue
`admin.createUser`, which sets `''` correctly — so this only bites manually-inserted users.

## 7. How to work here safely (recap)

- **Verify against REAL data or a screenshot**, never the mock harness alone (§0).
- Data changes: **snapshot first**, change `is_client` AND `raw.isClient` together, keep a
  one-line undo. Live tool the team uses — reversible beats clever.
- Code changes: append a self-contained `try/catch` `<script>` layer at the end of
  `index.html`; don't restructure the middle. Deploy = push dev + fast-forward
  `claude/new-session-9fhlp1`; verify the Vercel deployment goes READY.
- One clear next step at a time; the user is not a developer and has hit many dead ends —
  bias to reducing his workload and keeping everything reversible.
